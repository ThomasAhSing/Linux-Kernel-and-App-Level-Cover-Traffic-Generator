# Troubleshooting

## External browser mode

* Existing installations keep their original lab config. Follow README.md to replace only the browser section from `/opt/traffic-testbed/config.example.json`; setting `enabled` alone on the old config still selects local lab mode.
* External browsing is captured on the VM's normal network interface (or `any`), not `sink0`. HTTPS is encrypted; verify HTTP status and page URLs in the journal. Use Wireshark TLS/DNS filters for connection activity.
* `blocked request (origin/method/budget/schedule)`: check exact authorized origins and asset origins, GET/HEAD method, request budgets, schedule and emergency flag. Regional/consent redirects require explicit navigation authorization; never enable wildcard origins to silence the logs.
* A browser service network-mode mismatch means you selected the wrong unit. Use `traffic-browser` for external config, `traffic-browser-lab` for lab config, or let `traffic-schedule.service`/`manual.sh` choose. External service has no namespace or local HTTP dependencies.
* DNS/HTTPS failures: verify the VM has internet and working DNS, correct system time, and trusted CA certificates. Certificate checks remain enabled. A 403/429/challenge is a failed request; reduce/stop the workload or choose an appropriate endpoint.
* The browser lock moved to `/run/traffic-testbed-browser/browser.lock`. Both browser services and the manual wrapper use the same systemd RuntimeDirectory and unprivileged account. Do not run the Python entry point directly as root.

## Original isolated lab mode

The entries below describe the local fixture. Its browser service is now named `traffic-browser-lab`; `traffic-browser` is the new external service.

* **Windows / WSL denied:** this service requires an Ubuntu Linux kernel and systemd. Portable tests work on Windows, but kernel tests require a Linux VM. Do not treat mocked tests as live kernel verification.
* **`modprobe: FATAL: Module pktgen not found`:** inspect `grep CONFIG_NET_PKTGEN /boot/config-$(uname -r)`. Install the matching Ubuntu modules-extra package if available, or use a pktgen-enabled kernel. Containers commonly lack module-loading capabilities; use a VM.
* **Config rejected:** run `sudo /opt/traffic-testbed/venv/bin/python /opt/traffic-testbed/testbed.py validate`. Destination must be explicitly `10.203.0.2`, allowlisted, with `lab0`; production never accepts another destination. Blank defaults intentionally disable pktgen. Inspect the full exception in the journal. Configuration for a component is validated independently of the other component.
* **Service immediately exits:** inspect its journal for disabled config, emergency flag, outside-window refusal or request-limit completion. None is a generator failure. The browser request limit applies per service activation; use a higher limit or longer interval if a full working-day workload is needed. A deliberate manual restart resets that limit.
* **HTTP timeouts:** start `traffic-http.service`. Inspect its journal and namespace addresses. Only the supplied exact pages are allowed; external assets and redirects are blocked. HTTPS requires an operator-supplied trusted certificate; the included server uses HTTP.
* **Chromium missing:** rerun the pinned venv's `playwright install --with-deps chromium` with `PLAYWRIGHT_BROWSERS_PATH=/opt/traffic-testbed/browsers`, as in install.sh. Do not point it at a personal browser profile. Inspect `journalctl -u traffic-browser` for missing libraries or resource exhaustion.
* **Permission denied on a manual config:** the browser runs as `traffic-testbed`. Its config and all parent directories must be readable/traversable by that account. The installed config uses group traffic-testbed and mode 0640. The kernel workload must run as root inside the namespace.
* **Duplicate instance / existing transient unit:** stop the relevant scheduled or `traffic-manual-*` service before rerunning; scheduled/manual controllers share a lock. If systemd start-rate limiting was reached, use `sudo systemctl reset-failed traffic-browser traffic-pktgen` after fixing the cause.
* **Namespace collision:** pre-existing `tt-source` or `tt-sink` is rejected. Never remove someone else's namespace to make installation work. Inspect `ip netns list` and the ownership marker `/run/traffic-testbed/owned`. A partial setup owned by this project can be cleaned with `/opt/traffic-testbed/lab.sh down` after stopping all its processes.
* **Cleanup says namespace occupied:** inspect `sudo ip netns pids tt-source` and `sudo ip netns pids tt-sink`; stop test/capture processes and services before retrying. A tcpdump process also keeps a namespace occupied. Namespace deletion is intentionally refused while occupied.
* **Pktgen errors or count remains zero:** inspect `journalctl -u traffic-pktgen`, the per-device proc file during execution and `ip -s -n tt-sink link`. Stop/reset before retrying. ExecStopPost logs statistics and removes configuration. Never use a host-wide pktgen reset as a shortcut.
* **Unexpected termination:** `journalctl -u traffic-pktgen` shows systemd exit reason (signal/OOM) and cleanup output even when SIGKILL prevents Python logging. `systemctl show traffic-browser -p Result -p MemoryPeak` helps inspect resource failures. Limits are conservative; avoid raising them without measuring the isolated VM.
* **Wrong schedule:** inspect `timedatectl`, the device timezone, NTP synchronization and `systemctl list-timers --all`. Catch-up triggers reconcile current time. Verify `traffic-schedule.timer` is enabled. systemd timers and userspace polling cannot provide real-time deadlines while the machine is suspended or starved.
* **Emergency stop:** `/opt/traffic-testbed/emergency-stop.sh` creates a persistent stop flag, disables scheduling and stops scheduled/manual units. Clear `/etc/traffic-testbed/DISABLED` explicitly when ready. Disabling a timer alone does not stop a running workload; use the supplied stop commands.
